# 法務助理需求與驗收基準

版本：研究基準 0.3。更新日期：2026-11-09。

這份文件根據使用者已提供的功能方向整理，作為 13 個框架的共同比較基準。未確認的產品選擇另列，不將研究假設當作使用者已核准的最終規格。

## 已確認前提

- 使用對象為個人律師或法律事務所，透過 LINE 私訊與客戶群組互動。
- 已有臺灣 LINE 官方帳號；使用者於 2026-11-03 回報 Messaging API 已啟用，能看到 Channel 資訊。尚未實測 webhook、收訊與通知。
- Google 個人帳號與 Workspace 都納入研究、選型與支援規劃，未來很可能需要串接 Workspace。本輪先測個人帳號；使用者目前無法提供 Workspace 測試環境，只延後該環境的實測。
- 僅採雲端或託管服務，不以自家電腦或 NAS 為正式部署環境。
- 未來能搬到不同平台部署，納入正式選型與驗收。搬移需涵蓋程式、資料與未完成工作，客戶持有帳號或能匯出資料不能單獨視為通過。
- 文件與測試人物僅使用 `範例客戶甲`、`範例客戶乙`、`範例律師甲` 等明確示意名稱。
- 需要主動排程與通知，不能只在收到使用者訊息時工作。

## Google 帳號支援與驗收範圍

選型與設計都必須考量個人帳號及 Workspace，說明授權、管理員政策、文件所有權、分享與部署差異，以及未來切換或加入 Workspace 的方式。不能因本輪缺乏 Workspace 環境，就選擇無法合理支援 Workspace 的方案。

本輪實測報告分開記錄個人帳號的測試結果、Workspace 的文件相容性證據與待實測項目。缺少 Workspace 帳號不阻擋本輪個人帳號原型，但 Workspace 仍維持「尚未實測」，具備環境後再驗證適用的 Gmail、Drive、Calendar 流程與管理限制，不能直接標示整體 Google 整合已驗收完成。

## 核心資料與來源

| 資料 | 用途與必要關係 |
| --- | --- |
| 律師身分 | LINE Provider 與 user ID 綁定已核准的律師帳號，另保存可操作案件。 |
| 客戶 | 使用內部客戶 ID。名稱只供顯示，同名不自動合併。 |
| 案件 | 固定案件 ID、案別、客戶、案由、可選的正式法院案號、負責律師與狀態。 |
| 群組關係 | 明確登記案件與群組 ID。不依群組名稱猜測，不預設一組只能有一案。 |
| 文件 | 案件 ID、原始來源 ID、檔案 ID、版本或雜湊、取得時間與公開範圍。 |
| 訊息與信件 | 來源事件、message ID、當時文字或必要快取、編輯與收回狀態、案件連結。 |
| 待辦 | 來源訊息、負責律師、狀態、提醒時間與完成紀錄。 |
| 待確認動作 | 明確的案件、操作、接收者、內容版本、到期時間及確認者。 |
| 通知 | 來源工作、目標群組或使用者、內容版本、重試識別碼與接受或確認狀態。 |
| 記憶 | 偏好、經核准的案件事實與來源分開保存，包含修正及失效狀態。 |

以上是研究需要辨識的資料，不要求第一版拆成多個服務。Agent 對話紀錄不能取代案件資料與外部操作紀錄。Google 原文與衍生資料保存須另對照 [Google 整合研究](google-integration-research.md)。

## 角色與操作規則

| 操作 | 律師私訊 | 已登記客戶群組 | 程式端檢查 |
| --- | --- | --- | --- |
| 登記案件、綁定群組 | 白名單律師操作 | 是否允許群組指令待確認 | 發話者身分及案件管理權。 |
| 接收文件 | 可接收後指定案件 | 接收文件並依案件規則處理 | 案件範圍、類型與歸檔規則。 |
| 查信與彙整 | 白名單律師操作 | 不開放直接搜尋律師信箱 | 信箱授權及可見範圍。 |
| 知識庫問答 | 依律師權限 | 僅取可公開且與本群組案件相符的資料 | 檢索前套用權限，不只在輸出時過濾。 |
| 建立 Calendar 活動 | 律師確認後執行 | 群組資料可作來源，不能代替律師確認 | 確認身分、內容版本與目標行事曆。 |
| 轉發信件與進度 | 律師指示或預先設定的通知規則 | 接收符合公開範圍的內容 | 目標、案件、內容及附件權限。 |
| 完成或延後待辦 | 白名單且具案件權限的律師操作 | 客戶回覆不能自動視為律師結案 | 操作者與待辦權限。 |

未取得發話者 ID 時，不執行律師限定操作。不是白名單不代表能讀所有公開資料，仍需檢查當前案件與群組關係。

## 卡片優先的互動設計

使用者於 2026-11-06 確認此設計方向，後續安排原型實作與驗證。目前尚未實作，卡片版型、按鈕文案與摘要頻率仍待驗證。

預設互動採「摘要先看、細節再查、操作直接完成」，讓助理先整理好需要判斷的資訊，降低律師閱讀長篇通知與翻找聊天紀錄的負擔。

- 每張卡片只處理一件事，清楚列出哪個案件發生什麼事、現在需要律師決定什麼，以及可執行的操作。
- 原始信件、附件清單與判斷依據放在「查看來源」或「查看詳情」，需要時再閱讀。詳情與文件連結仍依案件權限顯示。
- 待確認歸檔、行程確認與內部待辦集中在律師私訊處理。客戶群組只接收符合公開範圍的內容。
- 日常摘要以尚待處理的事情為主，例如「今天有 3 件事需要你處理」，再逐項查看與操作。已完成項目退出待處理清單，處理紀錄保留。
- 按下操作後顯示處理狀態，區分處理中、已完成、失敗與結果待確認。收到按鈕回應不等於外部操作已完成。

### 歸檔確認示意

> **範例客戶甲｜收到新附件**
>
> 已暫存「補充資料.pdf」，請確認歸檔案件。
>
> 確認歸檔｜改選案件｜查看來源

示意文字中的案件名稱只供顯示，實際操作沿用案件 ID 與待確認動作。附件先及時取得並暫存，歸檔確認不等於同意對客戶公開。群組通知仍依各自的確認與通知規則處理。

卡片操作沿用既有身分、案件、內容版本與到期檢查。來源修改、收回或操作過期時，舊卡片不能繼續執行。重複點擊也不能重複歸檔、建立活動或發通知。卡片優先呈現的同時，保留文字指令與必要補問。

### 待原型驗證

- [ ] 先在律師身分與案件綁定基礎上，用合成案件驗證附件歸檔確認卡片，涵蓋查看來源、改選案件及操作結果回報，對應 R04、R06。
- [ ] 用同一套互動驗證行程確認，讓律師先看案件、時間與目標行事曆，再決定建立或修改，對應 R10。
- [ ] 驗證待處理摘要、完成後退出清單，以及等待確認時重啟後接續工作，對應 R08、R15、F09。提醒時間與頻率另行確認。
- [ ] 檢查手機與桌面 LINE 的閱讀和按鈕操作、長檔名與多附件詳情，以及來源失效、過期和重複點擊時的回應。Flex 與 Postback 的介面選擇依 [LINE 互動介面研究](line-api-research.md#群組與私訊互動介面) 實測。

本設計參考 [life 的待處理卡片](https://github.com/mattabate/life-distributable/blob/85258aca74d265769ca3e7e183c4aaabc4eb0dcf/app/Life/Sources/AskCards.swift)，借鏡其集中呈現待決定事項的方式。

## 功能與驗收案例

| 編號 | 功能與觸發 | 可觀察的完成條件 |
| --- | --- | --- |
| R01 | 律師登記案件 | `//登記案號 民事 範例客戶甲 侵權行為` 建立案件資料。同一事件或操作重送不多建案件，內容相同的新操作先確認是否另案，資料不足時補問。 |
| R02 | 建立或指定 Drive 資料夾 | 顯示名稱可為 `民事_範例客戶甲_侵權行為`，保存實際 folder ID。已存在或重試時不建立重複資料夾。 |
| R03 | 群組與案件綁定 | 具權限律師確認關係。多案件群組出現歧義時不猜測歸檔目標。 |
| R04 | 接收 LINE 文件 | 及時取得附件並保存來源，成功後歸入正確案件。取得失敗時能追查並提示補傳。 |
| R05 | 定時掃 Gmail | 處理指定時間或同步游標之後的信件及附件。律師已讀過的信仍不漏處理。 |
| R06 | 辨認信件案件 | 使用正式案號、已登記對應與文件線索。線索矛盾或無法確定時進待確認清單。 |
| R07 | 通知案件進度 | 只發至登記的案件群組，符合通知規則，不包含其他案件或內部討論。 |
| R08 | 整理客戶訊息 | 固定時間提供未處理問題、來源與必要附件。已完成項目不反覆提醒。 |
| R09 | `//檢查信件` | 回傳 Asia/Taipei 當日信件摘要、數量與來源，明確呈現無法讀取或尚未同步的狀態。 |
| R10 | `//行事曆` | 整理日期、時間、法院、案件與行事曆，缺資料時補問。律師確認後建立，回傳結果。 |
| R11 | `//轉發信件` | 先辨識指定信件與目標案件。附件採受控連結，目標客戶可讀且其他未授權者不可讀。 |
| R12 | `//已登記案號` | 僅列出律師可查閱的案件，區分內部案件 ID 與法院正式案號，未登記案號不編造。 |
| R13 | 知識庫問答 | 答案可追溯至核准來源。資料不足、法域不符或相互矛盾時轉交律師，不編造依據。 |
| R14 | 長期記憶 | 跨對話保存核准偏好與事實，能查詢、修正、刪除及追溯來源。失效來源不繼續影響回答。 |
| R15 | 主動工作與通知 | 沒有新 LINE 訊息時仍可啟動排程。服務重啟後保留尚未執行的工作與待確認事項。 |

每個案例都使用共同的合成案件資料，再分別由候選框架實作。不能為不同框架放寬角色權限或通知正確性要求。

## 恢復與錯誤驗收

| 編號 | 注入情境 | 必須觀察的結果 |
| --- | --- | --- |
| F01 | LINE 重送或同一信件再次掃到 | 去重，不重複歸檔或通知。 |
| F02 | 外部操作成功後、保存結果前中斷 | 依各 API 的識別碼核對或防重複。LINE Push 在二十四小時內沿用原 retry key，逾期且結果不明時停止自動重送、轉人工確認，不宣稱能查出個別送達。 |
| F03 | 訊息編輯、收回與原文亂序 | 不讓後到的原文恢復失效內容。舊確認與衍生摘要失效，不將編輯當成新的操作指令。 |
| F04 | Google 權杖失效 | 停止依賴該授權的工作，要求重新授權，保留待辦與進度。 |
| F05 | API 逾時或 5xx | 按服務規則重試，保存操作識別碼，無法確定結果時待確認。 |
| F06 | 月額度不足或暫時限流 | 分開分類，避免持續重試已無法發送的通知。 |
| F07 | 客戶冒充律師或文件含指令 | 不修改白名單，不取得額外案件權限。 |
| F08 | 封鎖、退群或文件無權限 | 明確記錄失敗或未確認狀態，不宣稱已讀或已完成交付。 |
| F09 | 等待律師確認時重啟 | 可恢復相同待確認內容。來源已修改或過期時，拒絕舊確認。 |
| F10 | 同名客戶、多案件、多個律師 | 不依名稱合併身分，不跨案件歸檔、回答或通知。 |
| F11 | Google 來源權限撤銷或來源失效 | 相關快取、索引與衍生摘要停止供檢索，依保存規則清理。不以曾讀取過作為持續讀取權。 |
| F12 | LINE 驗簽或事件保存失敗 | 拒絕進入背景工作，不執行外部操作。保存失敗回非成功並告警，紀錄不含敏感正文。 |

測試集中的錯誤接收者、越權操作與重複外部操作，目標均為零。這是個別測試集的驗收要求，不宣稱正式環境永不失誤。案件辨識不確定時先交給律師，不能為提高自動化比例犧牲正確性。

## 跨平台搬移驗收

2026-11-09 新增。以下是原型與選型的必要條件，尚未執行。各候選至少提出一個不同供應商的目標平台，沿用相同案件規則、語言、框架與固定版本；同平台重啟或重新部署不算通過。原型安排與成本記錄見 [跨平台部署研究](deployment-portability-research.md)。

| 編號 | 演練情境 | 可觀察的完成條件與證據 |
| --- | --- | --- |
| M01 | 同一套程式在另一平台執行 | 保存來源與目標的 commit、套件鎖定檔、圖與資料庫版本、部署步驟及差異。容器路線使用相同映像雜湊；只更換設定與平台串接，不改案件規則或流程圖。若需要改核心，列出未通過原因及修正成本。 |
| M02 | 資料搬到獨立目標資料庫 | 匯出並還原案件、身分權限、記憶、來源失效狀態、待辦、checkpoint 與操作紀錄。比對筆數、固定 ID、關聯、關鍵欄位及正規化後雜湊；時間、大整數與 JSON 不失真，未授權者仍無法存取。移除原資料庫存取權後功能仍可執行。 |
| M03 | 未完成工作與舊卡片接續 | 待執行、重試、等待確認及已過期工作均保留原 ID、來源版本、權限與到期時間。搬移前的有效卡片可在目標接續；已完成、過期、被收回或被修改的內容不能重做。測試舊、新入口重送及重複點擊，符合 F01、F09。 |
| M04 | 外部成功或結果不明時搬移 | 保留外部操作 ID、結果與原 retry key，已確認完成的 Drive、Calendar、LINE 操作不重做。結果不明時按 F02 處理，LINE retry key 超過有效時間不自動重送；保存核對結果與待人工處理清單。 |
| M05 | 排程與掃信切換 | 保留 Gmail 游標、Asia/Taipei 業務時間、應執行時間及去重識別碼。測試切換前後、跨日、延遲及重複觸發，沒有漏掉的已保存工作，也不重複提醒；舊排程與舊工作領取已停用。 |
| M06 | Google 授權、密鑰與入口交接 | 盤點 OAuth client、回呼網址、LINE webhook、網域、模型憑證與秘密管理權限。加密權杖另以受控方式交接，平台 KMS 金鑰無法攜出時驗證重新加密或重新授權流程；原始密鑰不進匯出報告或 repo。目標可更新授權，撤銷後符合 F04、F11。 |
| M07 | 切換失敗與回復 | 測試舊端仍有在途工作，以及新端開始寫入後需要回復的情境。確認舊工作者、排程與工作領取停止，在途操作已完成或列入結果不明清單後，才啟用新端外部操作；無法確認時保持停止。切換前已回覆接收成功的事件與已保存操作不遺失。回復先核對增量與外部結果，不直接重放舊快照。保存切換、停止寫入與恢復的時間及核對紀錄。 |
| M08 | 搬移成本與離開舊平台 | 保存程式差異、實作與驗證工時、雙平台重疊支出、資料傳輸、測試 API、人工處理、停機與恢復時間。撤銷舊平台測試權限後，在目標重跑搬移後必要的 R、F、M 案例。正式搬移前確認費用、停機與恢復時間上限；上限尚未確認時不得宣稱符合預算或時間要求。 |

測試集要求錯誤接收者、越權、遺失已確認接收的事件及重複外部操作均為零，不宣稱正式環境有絕對保證。結果不明的外部操作可以保持待核對，不能直接標成成功。只有模擬工具通過時，LINE、Google 與兩個雲端平台仍標為尚未實測。M01 至 M08 全部通過且正式搬移上限已確認前，不標示跨平台搬移已驗收。

## 起步功能順序

1. 律師身分綁定、案件登記與群組對應。
2. LINE 附件接收、Drive 歸檔與操作紀錄。
3. 定時掃信、案件辨識、待確認與群組通知。
4. 客戶訊息彙整、待辦處理與定時提醒。
5. 開庭行程確認及 Calendar 整合。
6. 知識庫回答與可管理的長期記憶。

這是驗證與開發的建議順序。研究階段仍同時檢查後段功能的授權、資料與框架限制，避免選型後才發現無法支援。

## 保留為產品選擇的事項

- 一個群組可能對應多案，第一版是否限制為單案仍待確認。
- 律師固定提醒時間、安靜時段、未確認後的再次提醒方式與通知額度分配。
- 哪些案件進度允許自動通知，哪些信件與附件必須先由律師確認。
- 客戶如何取得受控文件，是否具 Google 帳號，是否需要登入頁面。
- 知識庫格式、來源核准、適用法域及更新責任。
- 正式法院案號的格式、補登方式，以及同一案件是否有多個程序案號。
- 服務的使用人數、預算、保存期限與正式部署區域。

此基準不包含自動計算法定期限、代律師作成法律判斷、法院遞狀或自動寄出 Gmail。新增這些功能時，另列需求與驗收條件。
